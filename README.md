# MCTiers — offline edition

> **Note:** this folder also contains a second, unrelated project: [`namemc/`](namemc/) — an
> offline NameMC-style site with local accounts, skin/cape uploads and bundled fonts. Its own
> instructions live in [`namemc/README.md`](namemc/README.md).

A static Minecraft PvP tier list site (domain: crakedmctiers.gg, server IP: 130.78.218.210:25606) that
runs with no backend. The roster starts empty: players create local accounts, and a single **admin**
account sets every tier. Points, titles and the overall leaderboard are calculated in the browser.

## Open it

**Easiest:** double-click `start.bat`. It starts the preview server and prints the URLs.

```
http://localhost:4173/          <- MCTiers
http://localhost:4173/namemc/   <- NameMC
```

Or run it manually:

```powershell
node tools/serve.mjs 4173
```

You can also open `index.html` directly (double-click) — every page works from `file://` too,
since nothing on the site needs a server.

> If the pages come up blank, the preview server is not running. Start it with `start.bat`
> (or the command above) and reload. `tools/serve.mjs` now serves directory indexes,
> answers `404` for missing files instead of silently returning the home page, and sends
> `Cache-Control: no-store` so edits appear on the next reload.

## Accounts

| Account | Password | Can do |
| --- | --- | --- |
| `admin` | `admin1234` | Add/delete players, set every tier, set skins, export/import the roster |
| any other name | whatever the player chose (optional) | View their profile and set their own Minecraft skin — tiers stay read-only |

- Accounts live in `localStorage` (`mctiers.accounts.v1`); the session is `mctiers.session.v1`.
- The admin account is seeded automatically on first load if it is missing.
- `admin` is a reserved name, so a player cannot register it.
- Passwords are a local obfuscation hash, **not** real authentication. This is a fan-made static
  copy, not a secure login system.
- Staff (`admin`) profiles are never ranked.

## Editing tiers (admin)

1. Open **Log in** → `admin` / `admin1234`.
2. Add a player from the admin panel, or delete an existing one.
3. Press **Edit tiers** on a player and pick `HT1`–`LT5` per gamemode. Changes save instantly and the
   leaderboard updates.
4. **Export roster** downloads every local account as JSON; **Import roster** restores a backup.

Points per tier: HT1 60, LT1 45, HT2 30, LT2 20, HT3 10, LT3 6, HT4 4, LT4 3, HT5 2, LT5 1.

## Minecraft skins

Players do not need an account on any external site. In **My account → My Minecraft skin** they paste
either their Minecraft username (`Notch`) or their NameMC profile link
(`https://namemc.com/profile/Notch`). The site stores only the name and renders the skin from
`mc-heads.net`, falling back to `minotar.net`, then to a generated pixel avatar when offline.

The admin can fix a player's skin from the tier editor on the admin panel.

## Server image

`assets/img/server.svg` is the source artwork and `assets/img/server.png` is the shipped
raster copy used by the site. To use your own photo, save it as `assets/img/server.png`
(any PNG/JPG, square works best) — every server row picks it up automatically, with the SVG
as the fallback.

## Motion

The site uses CSS transitions/keyframes only:

- staggered entrance for top players, gamemode tiles, tier columns, table rows, titles and stats
- sections fade up as they scroll into view (JS adds the reveal class, so content stays visible if
  scripting is off)
- floating hero logo, pulsing admin badge, sheen on primary buttons, hover lift on cards and rows
- animated toasts and the slide-in navigation drawer

Everything is disabled automatically for `prefers-reduced-motion: reduce`.

## Fonts and motion

- **Geist** (bundled, variable 100–900) everywhere — the exact font file the live site serves,
  verified by SHA-256. Body text sits at weight 500, headings/UI chrome at 700, buttons at 600.
- **MCTIERS wordmark** (`assets/logo.svg`) is generated by `tools/make-logo.mjs`: "MC" is carved
  from a grass block, "TIERS" from a gold block, with 3D extrusion, hard outline and shadow.

Motion runs on `transform` and `opacity` only, images carry explicit dimensions and lazy
loading. The sticky header uses a light backdrop blur, and the glass surfaces keep their blur
radius small so scrolling stays smooth.

The **player profile page is deliberately lightweight**: `assets/js/fx.js` detects
`body.page-profile` and skips the particle canvas, shooting stars, cursor halo, card tilt,
magnetic buttons, ripples, spotlight and count-up entirely, so opening a profile is instant.

The **sun icon** in the header toggles all animation on/off and remembers the choice in
`localStorage` (`mctiers.motion.v1`). Motion is on by default even when the OS has animation
effects disabled; a safety class (`html.settled`) guarantees the page is always fully readable
even if the browser never paints an animation frame.

## The roster

The site ships with a **demo roster of 21 real Minecraft PvP players** (Technoblade, Dream,
TommyInnit, GeorgeNotFound, Sapnap, Vechs, ilMango, …) defined in `assets/js/data.js` under `roster`.

- On the very first run — when no player account exists yet — the roster is seeded into
  `localStorage` with tiers in all eight gamemodes, a region, a date and a written description.
  Your own accounts are never overwritten.
- Each player has a **Minecraft username**, so their real skin is pulled from mc-heads when the
  browser is online (with a generated pixel avatar as the offline fallback).
- The admin can restore the demo roster at any time with **Restore demo roster** in the admin panel.

## Admin: editing a player

Open a player from the roster table (`account.html?edit=Name`) and the admin gets:

- **Description** — a 400 character text area that replaces the auto-generated summary on the
  player's profile.
- **Profile look** — the full editor (avatar/skin upload, Discord avatar link, banner, wallpaper)
  applied to *that* player, so the admin can change the picture of anyone in the roster.
- **Tier selects** for all eight gamemodes, saving instantly.

## Profile look (skin, banner, wallpaper)

Both the player dashboard and the admin panel have a **Profile look** editor:

- **Avatar / skin** — upload a picture from your device, paste a direct image URL (a Discord avatar
  works), or paste a Minecraft username / NameMC link as before. Images are downscaled to 256×256
  and stored locally as a data URL.
- **Profile banner** — a wide strip across the top of your profile. Upload it or paste an image URL
  (downscaled to 1920×640).
- **Profile wallpaper** — the background of your whole profile page. Upload it or paste an image URL
  (downscaled to 1920×1200).
- **Connect with Discord** — paste the address of your Discord avatar image (Discord → your profile →
  right-click your avatar → *Copy Image Address*). No OAuth and no server involved, so nothing ever
  leaves the browser.

### The 64×64 skin from your photo

When you upload a photo it is also turned into a **real 64×64 Minecraft skin texture**:

- The photo is mapped onto the head (front, both sides, top and back).
- The body, arms and legs are tinted using the photo's own average colours.
- The texture is drawn with the standard Minecraft layout — head at (0,0), body at (16,16),
  arm at (40,16), leg at (0,16) — and rendered as a blocky character on your profile.
- The character is drawn in the classic 3/4 view: every part gets a front face plus an
  isometric side face (`matrix(.866, .5, 0, 1, 0, 0)`), with the left arm and leg mirrored.
- The editor shows the generated texture next to your avatar so you can see the 64×64 file itself.

### The profile card

The profile page follows the classic Minecraft profile layout:

- your **photo is the background** of the banner, with the player name written across the top
- the **character stands on the photo**, rendered from the 64×64 skin
- a **64×64 skin box** sits on the right showing the raw texture
- the player name is repeated underneath in a handwritten style

Everything is stored in `localStorage` on the device that saved it. If the browser storage is full the
save is refused with a toast instead of silently breaking the account.

## Tier tests (Minecraft ↔ website)

`minecraft-plugin/` contains a **Paper 1.21.11** plugin that connects the game server to the
website chat. `tools/serve.mjs` exposes a small local API (`tools/hub.mjs`) that both sides talk
to; it stores its state in `data/tiertest.json`.

1. A player runs `/tiertest` in game and gets a six character code.
2. On the website they open **Chat** → **New** → name the chat `get tier` → paste the code.
3. The code is verified and the player is put in a thread with a **tester** — anybody on the site
   who holds a rank, plus the admin.
4. The tester runs the fight, picks the gamemode and tier in the website and finishes the test.
5. The plugin announces the new tier in game and it lands on the leaderboard.

Rules the hub enforces:

- a **tester can never set their own tier** (the API answers *“You cannot set your own tier.”*)
- only accounts flagged as testers can award tiers
- plugin facing endpoints (`/api/tiertest/code`, `/api/tiertest/pending`) require the shared
  `x-tier-token` header, everything else is local-only

The website merges the hub into its own roster on load (`MCTApp.syncHub()`), so a tier awarded by a
tester on one computer reaches the player on another.

See [`minecraft-plugin/README.md`](minecraft-plugin/README.md) for the build and install steps.

## Themes

The header has a theme picker (the palette icon next to the Motion button) with three options:

| Theme | What it does |
| --- | --- |
| **Glass** | Default. Frosted, blurred surfaces with layered highlights and gold rim lights |
| **Solid** | Flat, opaque panels with no blur — the fastest option |
| **AMOLED** | Pure black surfaces for OLED screens, hairline borders, no glows |

The choice is stored in `localStorage` (`mctiers.theme.v1`) and applied as `data-theme` on `<html>`
before first paint, so switching themes never flashes.

## Data notes

`assets/js/data.js` holds only reference data — gamemodes, the HT1–LT5 point table, title thresholds
and region codes. The roster is empty on purpose and is rebuilt from `localStorage`, so clearing site
data also clears every player account.
